# Sloth v1.0.0

Sloth v1.0.0 is the first public release candidate for the local HTTP diagnostic CLI. These notes are ready for the tag workflow; they do not assert that the GitHub Release exists before the tag is published.

## Included

- `inspect` performs one bounded request and reports total, DNS, connect, TLS, request-write, first-byte-wait, and body-transfer observations with explicit unavailable reasons.
- `diagnose` runs bounded baseline, connection-reuse, and concurrency experiments and applies six deterministic, versioned evidence rules.
- `export` writes a redacted `sloth.report/v1.0` document atomically, with optional bounded samples.
- `compare` validates compatibility, describes raw before/after deltas, and can return exit 3 for a configured p50/p95/p99 regression.
- CGO-free archives target Linux AMD64/ARM64, macOS AMD64/ARM64, and Windows AMD64. Each release includes SHA-256 checksums.
- Machine JSON, output streams, exit codes, safety ceilings, privacy boundaries, methodology, and report schemas are documented and tested.

## Verification

The release candidate passes formatting, vet, unit/integration/end-to-end tests, race detection, schema fixtures, privacy canaries, fuzz targets, deterministic network-failure tests, five-platform native smoke tests, GoReleaser snapshot verification, and installed-artifact workflow smoke tests. See the [v1 readiness review](../v1-readiness.md) for the evidence map.

## Known limitations

- Sloth reports client-side evidence and hypotheses, not confirmed internal root causes.
- HTTP/3, cryptographic code signing, notarization, and package-manager publishing are outside v1.
- Checksums detect accidental corruption but do not authenticate the publisher.
- Results can be confounded by the local client, network path, proxies, caches, multiplexing, workload differences, small samples, and coordinated omission.
- Default runs cannot support high-confidence p99 interpretations.

No performance, accuracy, reliability, usage, or adoption claim is made by this release.
